
# Desarrollo de la plataforma web

## dIAra | Obras a la vista

Responsable: Reychell Segura Fernández
Grupo 3 - Visualización de Datos
LEAD University - 2026

## 1. Objetivo

Desarrollar una plataforma web interactiva, accesible y fácil
de utilizar que permita a la ciudadanía consultar la información
disponible sobre las obras públicas monitoreadas por dIAra.

## 2. Tecnologías utilizadas

- HTML5
- CSS3
- JavaScript
- JSON
- Git y GitHub
- Python HTTP Server para pruebas locales

## 3. Evolución del diseño

### Versión 1

Se desarrolló la estructura inicial de la plataforma, incluyendo
la navegación, las secciones principales y la carga centralizada
de datos.

### Versión 2

Se incorporó una identidad visual propia denominada
"Obras a la vista", navegación tipo aplicación, tarjetas
interactivas, indicadores dinámicos y diseño responsive.

### Versión 3

Se mejoró la distribución de los elementos visuales y se
incorporaron un calendario interactivo, opciones de accesibilidad,
alto contraste, acceso flotante al asistente y un mecanismo para
compartir la obra.

## 4. Principios de visualización aplicados

### Jerarquía visual

Se priorizó la información más importante para la ciudadanía,
como el nombre de la obra, su ubicación, la última actualización
y los registros disponibles.

### Uso del color

Se seleccionó una paleta de colores verdes, dorados y fondos
claros para generar una identidad visual consistente.
Los estados de los datos se acompañan de textos y símbolos
para evitar depender únicamente del color.

### Reducción de carga cognitiva

La información se distribuyó en diferentes secciones,
tarjetas y explicaciones desplegables para evitar saturar
a las personas usuarias.

### Interactividad

Se incorporó un calendario que permite explorar los registros
por fecha y consultar los indicadores correspondientes.

### Accesibilidad

Se implementaron opciones para aumentar el tamaño del texto,
activar el alto contraste y adaptar la interfaz a diferentes
tamaños de pantalla.

Estas funcionalidades deberán validarse mediante pruebas
formales de accesibilidad y usabilidad.

### Comunicación de incertidumbre

Se diferencia la actividad detectada del avance contractual.
Los periodos sin información no se presentan como ausencia
de actividad ni como evidencia de atrasos.

## 5. Respuesta a la retroalimentación

Se priorizó una solución web ligera, adaptable a dispositivos
móviles y desarrollada con tecnologías que no requieren
infraestructura compleja.

La plataforma está preparada para recibir los datos procesados
por el módulo de automatización y para integrar las
visualizaciones y canales de comunicación del equipo.

## 6. Integración de módulos

Se conservaron los identificadores HTML acordados con el equipo
y se implementó un mecanismo centralizado para compartir
los datos entre los componentes de la plataforma.

## 7. Pruebas preliminares

Se realizaron pruebas locales de navegación, carga del JSON
de demostración, selección de fechas e indicadores dinámicos.

También se comprobó la adaptación móvil de la versión 2.
La versión 3 requiere una validación final en dispositivos
móviles y de todas sus opciones de accesibilidad.

Estas pruebas corresponden a una revisión técnica preliminar,
no a las pruebas formales con usuarios del público objetivo.

## 8. Limitaciones actuales

- Los datos utilizados actualmente son simulados.
- Los módulos de los demás integrantes están pendientes
  de integración.
- No se calcula el avance contractual a partir de fotografías.
- La plataforma todavía no está publicada.
- Las pruebas formales de usabilidad están pendientes.
